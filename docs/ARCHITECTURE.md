# CarbonMate 架构说明

## 分层

- `pages`：ArkUI 页面和交互状态。
- `components`：指标、标题、趋势图与记录行组件。
- `services`：记录、AI 识别、导出等应用用例。
- `domain`：行为模型、因子仓库、核算、积分和趋势逻辑。
- `data`：ArkData RelationalStore 本地持久化。
- `server`：本机部署的识别网关，负责请求校验、字段裁剪与转发，密钥只留在该计算机。

依赖方向为 `pages → services → domain/data`。DeepSeek Key 只保存在网关环境；移动端仅保存用户配置的网关地址和独立客户端令牌。

## 记录与核算

1. 用户选择一种行动。节电可以记具体行为次数，或明确选择设备报告的 kWh 计量模式。
2. 只有节电 kWh 计量模式会调用官方 2023 全国电力因子；其他生活行为保存活动和积分，不生成碳量。
3. `CarbonRecordService` 保存行为、因子 ID/版本、来源、碳量和积分。
4. `DBManager` 将行动记录与积分流水写入本机 ArkData。
5. 首页、数据页、图表与 CSV 汇总只接受已知因子 ID 和版本；旧 `DEMO_V1` 数值只保留为历史，不并入当前核算。

积分发放与碳量估算脱钩。照片识别仅生成候选草稿，用户确认并点击保存后才进入记录库。

## 尚未连接的能力

鸿蒙超级终端设备发现、分布式数据同步、家庭积分汇总仍未实现。后续设计须先明确设备授权、用户退出/撤销、重复记录、跨设备编辑和删除冲突规则，再接入官方分布式数据 API 并完成至少两台真实设备验证。
